# 中文使用指南：从数据到可编辑 Origin 图

[返回首页](../README.md) · [English](../README.en.md)

这个工具让 Codex 调用 Windows 本机 Origin，也可以作为 Python 脚本单独运行。绘图、保存和导出发生在 Origin 内；提供的数据决定图上的数值。

## 我应该先准备什么？

| 项目 | 是否需要 | 用途 |
|---|---|---|
| Windows + 已安装、可用许可的 Origin | 必须 | 原生绘图与 COM 自动化 |
| Python 3.10+ 与 Skill 依赖 | 必须 | 调用 Origin、解析规格和核验导出 |
| Codex 与已安装的 Skill | 自然语言工作流需要 | 把绘图要求转换为操作 |
| PowerPoint 桌面版 | 可编辑 PPT 需要 | 嵌入 Origin OLE 对象 |

已验证的本地环境为 OriginPro 2021 与 PowerPoint 16.0，其他版本需自行核对。Linux/macOS 可以验证规格，但不能执行本机 Origin COM 绘图。

## 安装：选一种方式

### 方式 A：让 Codex 安装

在具有 Skill 安装功能的 Codex 中发送：

> 从 https://github.com/jiahehu2000-lgtm/origin-scientific-plotting 安装 Skill，仓库路径 `skills/origin-scientific-plotting`。

然后在实际运行绘图的 Python 环境安装依赖：

```powershell
$originSkillPath = Join-Path $HOME '.codex/skills/origin-scientific-plotting'
python -m pip install -r (Join-Path $originSkillPath 'requirements.txt')
```

如果当前会话看不到 Skill，开启一个新会话再调用。

### 方式 B：下载 ZIP

打开 [Releases](https://github.com/jiahehu2000-lgtm/origin-scientific-plotting/releases/latest)，下载 Skill ZIP。解压后把包含 `SKILL.md` 的 `origin-scientific-plotting` 文件夹放到 `~/.codex/skills/`，再按上面的命令安装依赖。

ZIP 用于安装 Skill；四张完整演示的数据和配置在仓库中。

### 方式 C：克隆并手动安装

```powershell
git clone https://github.com/jiahehu2000-lgtm/origin-scientific-plotting.git
$originSkillPath = Join-Path $HOME '.codex/skills/origin-scientific-plotting'
if (Test-Path -LiteralPath $originSkillPath) {
    throw '目标 Skill 已存在，请先检查已有内容。'
}
New-Item -ItemType Directory -Path (Split-Path -Parent $originSkillPath) -Force | Out-Null
Copy-Item -LiteralPath './origin-scientific-plotting/skills/origin-scientific-plotting' -Destination $originSkillPath -Recurse
python -m pip install -r (Join-Path $originSkillPath 'requirements.txt')
```

只复制 Skill 子文件夹，避免把整个仓库当成 Skill 安装。

## 第一次运行：先检查，再画演示图

在完整仓库根目录运行以下命令。虚拟环境的同一个 Python 用于安装依赖和执行脚本。

```powershell
python -m venv .venv
& ./.venv/Scripts/python.exe -m pip install -r skills/origin-scientific-plotting/requirements.txt
& ./.venv/Scripts/python.exe skills/origin-scientific-plotting/scripts/origin_plot.py --doctor
& ./.venv/Scripts/python.exe skills/origin-scientific-plotting/scripts/origin_plot.py --spec examples/figures.json --validate-only
& ./.venv/Scripts/python.exe skills/origin-scientific-plotting/scripts/origin_plot.py --spec examples/figures.json --output results
```

`--doctor` 用于检查本机条件；`--validate-only` 检查数据和规格，不执行绘图。正式调用后应得到四张合成演示图：曲线与散点、对称误差棒、柱状图、行归一化混淆矩阵。

输出目录必须新建或为空。如果已经有 `results`，换一个新目录名，保留前次结果。

## 自己的数据怎么给？

先给出数据文件，并说明列、单位和图型。仓库自带的绘图规格使用数值 CSV、指定列名或明确的数值数组；其他输入格式可先整理为这些格式。

| 数据 | 需要说明的内容 |
|---|---|
| 曲线 / 散点 | X、Y 列名、单位、曲线顺序、图例 |
| 误差棒 | 均值和对称误差列，以及误差是 SD、SEM 或其他指标 |
| 柱状图 | 类别顺序、数值和单位 |
| 混淆矩阵 | 原始计数、行是真实类别还是预测类别、是否逐行归一化 |

工具绘制你提供的误差值，不会替你推算统计误差。矩阵归一化时保留原始计数，未测试行以缺失显示。

**可复制的曲线指令：**

> 使用 `$origin-scientific-plotting`，调用 Origin 绘制这个 CSV。`time_s` 是 X 轴，单位 s；`current_nA` 是 Y 轴，单位 nA。参考附件设置图框、字体和图例，导出 OPJU、PDF 和 EMF，检查数据以及最终版式。

**可复制的混淆矩阵指令：**

> 使用 `$origin-scientific-plotting`，用这个原始计数矩阵绘制混淆矩阵。行是真实类别，列是预测类别，按行归一化到 0—1，每格标数值，色标范围 0—1。未测试行保留缺失，导出原生工程和矢量图。

数值字段和支持的设置见 [figure-spec.md](../skills/origin-scientific-plotting/references/figure-spec.md)。

## 字体、白边和图框怎么统一？

提供一张参考图，同时说明图最终用于多大的版面。字体、字号、框线、图层尺寸和页面留白均可配置；默认演示样式不能当作所有期刊的标准。

> 这些图最后放进 PPT，每张宽度 5 cm。请按这个显示尺寸统一轴标题、刻度字号和边框；缩小页面外侧的多余空白，保证每个矩阵格子的数字不挤在一起，修改后逐张看预览。

页面宽度、图框宽度和 PPT 放置宽度是不同设置。缩放到 5 cm 后，文字也会一起缩放，因此要按最终尺寸检查可读性。

## 怎样做双击可编辑的 PPT？

生成绘图结果后运行：

```powershell
& ./.venv/Scripts/python.exe skills/origin-scientific-plotting/scripts/origin_to_ppt.py --manifest results/manifest.json --output example_figures.pptx --width-cm 5
```

或交给 Codex：

> 使用 `$origin-scientific-plotting`，把这些 Origin 图作为嵌入式 Origin 对象放进 PPT，每张宽 5 cm、锁定比例，添加中文备注，并检查排版。

要添加到现有 PPT 的副本，在脚本参数中加 `--template existing.pptx` 并指定新的输出文件名。工具不覆盖原 PPT。嵌入时会短暂使用剪贴板，期间避免复制其他内容。

生成后在桌面版 PowerPoint 中双击对象，确认 Origin 编辑器能打开。PDF、EMF 和 PNG 虽能显示图，但没有 Origin 工程的编辑结构；需要选择 OLE 嵌入流程。

## 常见问题

**没有 Origin，还能画吗？**

可以查看和校验规格，原生绘图需要本机 Origin 和有效许可。仓库不提供 Origin 安装包或软件许可。

**输出包含 SVG 吗？**

包含。它由 Origin 矢量 PDF 转换，PDF 和 EMF 则由 Origin 原生导出。

**图片成功生成就代表结束了吗？**

还要检查核验记录和预览，特别是最终显示宽度下的字体、数字重叠、图例裁切和页面白边。所有图核验通过后，批次清单才会标记完整。

**GitHub 检查通过等于所有 Origin 版本都支持吗？**

不是。云端检查的是可移植逻辑；实际 Origin 与 PowerPoint 的验证证据和边界见 [VALIDATION.md](VALIDATION.md)。

**`interactive_editing_tested: false` 是什么意思？**

OLE 对象结构已经核验，但辅助脚本没有自动执行双击编辑测试，需要在你的 PowerPoint / Origin 环境中确认。
